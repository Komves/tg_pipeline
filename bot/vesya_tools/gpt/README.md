# Веся: консультация и первоначальное подключение GPT

Изолированный от ПАРУС и старой команды `/proxy` процесс. Цена: 2990 ₽ разово, самозанятость, чек НПД владелец оформляет самостоятельно.

## Клиент

1. Пишет `/gpt` или «Веся, подключи мне GPT».
2. Веся регистрирует заявку в `/data/gpt_consultations.sqlite3`, сразу пишет владельцу Telegram ID и даёт кнопку **Выдать бесплатный код**.
3. Клиент видит реквизиты оплаты и кнопки «Я оплатил — загрузить квитанцию» / «У меня есть секретный код».
4. После оплаты присылает PDF или фото квитанции. Веся сохраняет Telegram file ID, хеш документа, банк и идентификатор операции, проверяет дубли, сумму 2990 ₽ и получателя.
5. Оригинальную квитанцию с реквизитами отправляет владельцу. Статусы «квитанция принята», «поступление сверено» и «чек НПД оформлен» независимы.
6. Если реквизиты и статус документа проходят проверку, создаётся индивидуальная учётная запись на отдельном GPT Agent с mTLS. Факт зачисления денег это не доказывает.
7. Клиент получает логин и первичный пароль в личном Telegram-чате, а ссылку на установщик — после настройки `GPT_INSTALLER_URL`.

## Бесплатный доступ

Владелец нажимает **Выдать бесплатный код** в своём уведомлении. Веся присылает код лично владельцу. Он привязан к Telegram ID клиента, действует 7 дней, одноразовый; повторная генерация отзывает старый неиспользованный код. Пользователь вводит код Весе.

## Административные команды (только владельцу)

- `/gpt_status` — проверка API Новосибирска.
- `/gpt_code TELEGRAM_ID` — выпустить бесплатный код.
- `/gpt_approve TELEGRAM_ID` — ручное принятие неоднозначной квитанции.
- `/gpt_paid_confirm TELEGRAM_ID` — отметить фактически сверенное поступление.
- `/gpt_npd TELEGRAM_ID` — отметить самостоятельно оформленный чек самозанятого.
- `/gpt_disable TELEGRAM_ID` и `/gpt_enable TELEGRAM_ID` — блокировка/восстановление только GPT.

## Render: секреты и переменные

Уже подготовленные пользователем переменные и Secret Files:

- `GPT_AGENT_API_URL=https://ru.paruslegal.ru:4460`
- `GPT_AGENT_API_TOKEN` — секретная переменная, не печатать.
- `GPT_AGENT_CLIENT_CERT_FILE=/etc/secrets/vesya-render.crt`
- `GPT_AGENT_CLIENT_KEY_FILE=/etc/secrets/vesya-render.key`

**Отдельно нужны реальные значения; не выдумывать:**

- `GPT_PAYMENT_DETAILS`: банковские реквизиты и инструкция для клиента. Пока не установлена, Веся не предлагает перевод денег.
- `GPT_PAYMENT_RECIPIENT`: точное наименование получателя из банковского чека. Пока не установлено, квитанция всегда требует ручной проверки и не открывает автоматический доступ.
- `GPT_INSTALLER_URL`: действительная HTTPS-ссылка на подписанный/проверенный Windows-пакет `GPT`. Пока её нет, Веся сообщает, что установщик ещё не опубликован.
- `GPT_OWNER_TG_ID`: при желании явно указать владельца (иначе первый ID из `ADMIN_USER_IDS`).

**Ограничение:** OCR/vision анализирует фото или первую страницу PDF с помощью модели, но не подтверждает зачисление платежа. Поддельные квитанции могут пройти форматные проверки; владелец сверяет поступление и блокирует сомнительный доступ. Не считаем платёж подтверждённым по одной квитанции.

## Защита

- Код хранится только как SHA-256; запись погашается атомарно.
- Не сохраняются открытые прокси-пароли в БД или административных уведомлениях.
- Регистрация кодов и квитанций обрабатывается до сырого текстового debug-логирования в `main.py`.
- Receipt hash и fingerprint операции уникальны в реестре; оригинал документа доступен владельцу через Telegram.
- Запросы Веси к API — mTLS плюс отдельный токен, без root/SSH.
- Старые `/proxy`, Nginx 4455 и ПАРУС не изменяются.
